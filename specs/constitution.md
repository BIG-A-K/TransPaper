# Constitution

このプロジェクトの設計原則。すべてのspecとコードはこれに従う。`constitution` フェーズでのみ更新する。

## 設計原則

1. **パイプライン分離**: 処理を独立した4ステージ（Segmentation → Translation → Collection → Composition）に分割し、各ステージは中間ファイル（JSON/PNG）を介して疎結合に連携する。ステージ単体でも実行可能とする。
2. **フォールバック安全性**: 外部リソース（MLモデル、APIキーなど）が利用不可でもクラッシュせず、縮退動作で処理を続行する。例: モデル未検出時は全ページを単一textブロックとして扱う。
3. **シングルバイナリ配布**: エンドユーザーがバイナリ1つをダウンロードするだけで使えることを最優先の配布形態とする。Python・uv等のランタイム依存を排除し、macOS / Linux のクロスプラットフォームをサポートする。
4. **レイアウト保存翻訳**: 翻訳後のPDFは元のレイアウト（図・表・数式の配置、ページ構成）を可能な限り維持する。テキスト領域のみを差し替え、非テキスト要素は原本からそのまま配置する。
5. **段階的移行**: Python版からRust版への移行はPoC検証→ステージ単位の実装→統合の順で段階的に進める。最優先はDocLayout-YOLOのcandle検証。移行期間中はPython版を正とし、Rust版が機能パリティを達成するまでPython版を維持する。

## 技術的制約

- Rust edition 2021以上、stable toolchain を使用する。nightly 限定機能には依存しない。
- ML推論は candle（HuggingFace公式Rust MLフレームワーク）を使用する。DocLayout-YOLOの推論がcandleで実現できない場合、Rust移行自体を中止する（No-Go判断）。
- PDF操作ライブラリはPoCで選定する。必要機能は「PDF読み込み・テキスト抽出・redaction（塗りつぶし）・テキスト配置・画像挿入」の5点。候補はmupdf-rs、lopdf、pdf-rs。いずれも要件を満たせない場合はRust移行を中止する。

## 用語定義

| 用語 | 定義 |
|------|------|
| Segmentation | PDFの各ページをレイアウト要素（text, image, table, caption, math）に分割する処理。DocLayout-YOLOによる物体検出で実現する。出力はSegmentBlockのリスト |
| Composition | 翻訳済みテキストを元のPDFレイアウト上に再配置し、最終PDFを生成する処理。原文のredaction → 翻訳テキスト配置 → 非テキスト要素の再配置の順で行う |
| redaction | PDFページ上の原文テキストを白色で塗りつぶして除去する処理。翻訳テキストを上書き配置する前処理として行う |
| bbox | ページ上の要素の位置を表す矩形座標 (x0, y0, x1, y1)。左上原点 |
